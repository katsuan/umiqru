# 🌊 うみくる 〜UmiQru〜

同じ場所の海の予報を、出どころごとに並べてくらべるツール。釣りや海あそびの前の下しらべ用。名前は「うみくる」（海のようすが先に来る）。英字は UmiQru（「く」を Q にする。そらくる＝SoraQru と同じ作り方）。キャッチコピーは「海のごきげん、くらべて先どり」。GitHub Pages でそのまま動く静的サイトで、サーバーは使わない。

公開URL: https://katsuan.github.io/umiqru/ （2026-11-06 公開。くらぶ〜Qlove〜の一覧（👾 きたく部、そらくるの次）に載せた。ポートフォリオにはまだ）

## できること

- 場所：港の名前・地名・緯度経度（`(20.43, 136.08)` のようなかっこ付きも。日本の外も）・今いる場所・地図（検索欄の横の地図のボタン。国土地理院の地図か写真を押すか、ピンを動かした所の緯度経度で見る。ズーム9より寄ると、潮汐表のある港（data/ports.json）が丸で出て、押すとその港の位置と名前を選ぶ。名前をつけると `緯度,経度=名前` になり、ウィジェットの Parameter にもそのまま使える。「コピー」で写すだけもできる。地図は Leaflet を cdnjs から、窓を初めて開いたときだけ読む。js/mappick.js）。`?q=城ヶ島` / `?q=20.4253,136.0814` のリンクで、その場所で開く
- 日記の「くらぶボットに送る」：釣果のある日記を、LINE でボットのトークの入力欄に入れて開く（`line.me/R/oaMessage/@ボット/?文`。送るのは使う人）。文は「📔 うみくるの日記 日にち／📍 緯度,経度 場所／潮：港（tide736.net）／時刻 魚｜潮 上げ2分 32cm（7%）」。ボットの ID は、ボットのカードのリンクの `&bot=@…` で覚える（その端末の localStorage。知らなければボタンを出さない）。ボットは時刻で記録と合わせ、tide736 の潮をシート「うみくるの日記」に残す（q-qlove-bot の 56_sea_diary.gs）
- くらぶボットの釣りの記録からのリンク（`?q=緯度,経度=名前&d=2026-11-12&c=0642~アジ_0810~`）：場所を開いたあと、日記のタブで、その日の釣果（時刻と魚。名前がなければ「魚」）を入れた「日記を書く」を開く。残すのは使う人が「残す」を押したとき。同じ日・同じ場所の日記がもうあれば知らせる（js/diary.js の prefillFromUrl・diaryPrefill）
- 同じ名前の場所がほかにもあるとき（鵜来島・柏島など）は、よさそうな所を開き、場所の行の下の「ほかにも「○○」があります」を開くと選びなおせる（Open-Meteo と国土地理院の地名さがしの両方から。ウィジェットには選んだ位置を渡す）。さがして開いたとき（検索・?q= のリンク）は、Q キットのトーストで「ほかにも○か所あります」と知らせ、「えらびなおす」でその欄を開く
- 「見る」を押したあと：ボタンは回る輪と「さがし中…」、知らせの行に「○○を読みこみ中…」と流れる線、前の場所の表示はゆっくり明るく暗く。読み終わると「○○を表示しました」（少しして消える）。空のまま押すと「場所を入れてください」
- 近い潮の港（30km 以内）と気象庁の地域は自動で選ぶ（国土地理院の市区町村コード → 気象庁の区分。海の上なら港とそのまわりで探す）
- 日本の出どころを先に：気象庁の天気・波・風の文（3日先まで）、6時間ごとの降水確率、警報・注意報（波浪・強風・濃霧など）、近くのアメダスのいまの風・気温（30km 以内。今日だけ）、潮汐表（tide736.net）
- 緯度経度で読む予報（Open-Meteo）：波4つ（欧州・米国・フランス・米国の細かい計算）、風4つ（気象庁 MSM・GSM・欧州・米国）、突風（GFS・IFS）、1時間ごとの天気・気温・降水確率・雨、水温、沖の海流、海面の高さ
- タブの上に、いま見ている場所・日時と、選んだ潮の港・気象庁の地域（どのタブでも見える）
- 送る：ページの下のほうの「○○の海を送る」の欄。「カードでおくるん」（見ている日・時刻の波・風・潮・天気・水温のめやすを、おくるんのお知らせカードで LINE に。カードのボタンでその場所のうみくるが開く）と「リンクを共有」（共有の画面がない端末ではコピー）。リンクとアドレス欄は `?q=` にウィジェットの Parameter と同じ書き方（同じ名前の場所がほかにもあるときは `?q=緯度,経度=名前`）
- タブで1つずつ：まとめ（ウィジェットと同じ 潮（天気も）→ 波 → 風 の順に、それぞれグラフ → 数字のカード。広い画面では1行に1つずつ、左にグラフ・右に数字（境目はどれも半分の位置。カードは2列）。風のグラフの下に、3時間ごとの向きの矢印（ウィジェットと同じく、予報を東西・南北に分けてならした向き。割れていればうすく）。はじめはここ）・潮・波・風・天気（ウィジェットと同じ並び）・日記。まとめの項目を押すとその欄に切りかわる。開いていたタブはこの端末に覚える
- 磯割（まとめの下。`data/isowari.json` の島だけ。いまは鵜来島）：渡船ごとに、その日に上がる磯のまとまり。鵜来島は家中・高見・家本の3つの渡船と、ホトバエ・カメ／マルサゲ・姫島北／グンカンの3つのまとまりが毎日1つずつずれてくり返すので、表を入れずに「最初の日・まとまり・渡船ごとのずれ・期間」から計算する（2026年10月〜2027年6月の渡船の発表と合うのを確かめた）。期間の外は「まだ発表されていません」。くり返しから外れる日は except に書く。渡船は船の色（家中 黄・家本 紫・高見 緑。磯割表と同じ色分け。data の color）で、ボタンに色の丸、表の列をうすく塗る（夜の画面でもまぶしくないよう背景にまぜる）。いつもの渡船はいくつでも選べる（押すたびに入れる・外す。この端末に覚える）。渡船のピルは「● 家中 グンカン」のように、その日の磯つき（選んだものは船の色でうすく塗る）。表は、選んでいなければ3つとも、選んだら選んだ渡船だけ（1つならまとまりの名前を全部）、7日ぶんの表に磯と昼（5〜15時）の波・風を並べる。行を押すとその日に。ウィジェット（SQriptable の sea）も、このデータを1日に1回読んで、大・中の下の行に渡船ごとの磯を出す（12時からはあす。Parameter に `鵜来島,家中` で渡船を選ぶ。いつもの渡船を選ぶと、ページの「iPhone のウィジェットにする」の Parameter にも入る）。出どころのページへのリンク（1つずつの行に）と「当日は渡船屋さんに確かめて」を添える。表が新しく出たら、期間と checked を直す（順番が変わっていたら、新しい period を足す）。見張り：週に1回（月曜の朝）、GitHub Actions（`.github/workflows/isowari-watch.yml`・`tools/isowari-watch.mjs`）が出どころのページの磯割表の画像（sources の watch に合うファイル名）の中身・ページの題名・更新日を前の回とくらべ、変わったところか、期間の終わりの31日前になったことを Issue（ラベル isowari）で知らせる。画像の中身は読まないので、知らせが来たら画像を見てデータを直す。前の回の記録は watch-state の枝。手で動かすときは Actions の「磯割表の見張り」から
- 海の日記（日記タブ）：「書く」で、日にち・はじめとおわりの時刻・渡船と磯（磯割のある島は渡船を選ぶとその日の磯が入る。ほかの所は磯・釣り座を書く）・写真と釣果（それぞれ時刻つき。写真は何枚でも。長い辺 1600px の JPEG にして残す）・見た海のようす（波・風・水の濁り）・したこと・メモを書く。写真の時刻は、写真の Exif の撮った時刻（なければファイルの時刻。その日のものでなければ、はじめの時刻）で、あとから直せる。場所は上でえらんでいる所
- 日記には、その日1日ぶん（0〜23時）の予報・潮・観測をいっしょに残す（`js/daydata.js`。4つの波・4つの風・天気・気温・降水確率・雨・水温・沖の流れ・海面、潮汐表の20分ごとの潮位と満潮干潮・月・日の出入り、気象庁の波の文、アメダスの実況）。ページで同じ場所・日を読んであればそれを使い、なければ、その日だけ読みなおす。約3か月前から6日先まで残せる（前の日は Open-Meteo の過去の値と潮汐表。あとから読んだ値と印をつける）。なおしても、日にちを変えなければ残したまま。1日ぶんは約5KB
- 日記は「はじめ → 写真・釣果（時刻の順）→ おわり」に並べ、それぞれの時刻の潮（上げ・下げと「上げ6分」・潮位 cm）・風・波を添える。押すと、大きな写真とその時刻の値（潮位とその日の高さの中の割合・潮の段階・潮回り・満潮干潮・まづめの中か・波と周期と向き・風と向き・突風・天気・気温・水温・沖の流れ。アメダスは残したときの1時間以内だけ）。前・次で順に見られる。下に、その日1日の表（1時間ごと。はじめ〜おわりに色、写真・釣果の時刻に印）
- 月のカレンダー（週のはじまりは月曜が既定。Q 共通の `week-start.js` で、ほかの Q ツールと同じ設定）で見て、写真のある日は写真の丸、ない日は点。日を押すとその日の日記、場所を押すとその場所のまとめが開く
- 分析用に書き出す：写真・釣果1つを1行にした CSV（日付・時刻・渡船・磯・魚・匹・cm と、その時刻の月齢・潮回り・潮位差・潮位・高さの割合・上げ下げ・潮の分・満潮から何分・まづめ・夜・波・周期・向き・風・向き・突風・天気・気温・降水確率・雨・水温・沖の流れ・見た海・メモ）。表計算ソフトで開けるよう BOM つき
- 日記を送る：日記ごとに「カードでおくるん」（見た海・したこと・釣果（時刻と潮の段階つき）・メモと、はじめの時刻の予報を、おくるんのお知らせカードで LINE に。カードのボタンでその場所のうみくるが開く。写真はこの端末の中だけにあるので、カードには入らない）と「共有」（端末の共有の画面で、文・リンクと写真をいっしょに。共有の画面がない端末では文をコピー）。カードの決まり（色・ボタン・from）は `js/card.js` 1か所で、上の「○○の海を送る」と同じ
- 日記と写真はこの端末のブラウザ（IndexedDB の `umiqru-diary`）にだけ残す。ほかの端末や人には送らない。消えないよう `navigator.storage.persist()` を頼み、JSON に書き出し・読みこみできる（写真も入る。同じ id は読みこんだほうにする。スマホは共有の画面から「ファイルに保存」）。前の形の日記（hour・catches・photos・snap）もそのまま読める。ホーム画面に置く案内（`js/install.js`）：スマホのブラウザとアプリの中のブラウザ（LINE など）で、ホーム画面から開いていないときは、日記タブの上に「日記は、ホーム画面のうみくるで書くのがおすすめ」と、わけ（iPhone の Safari はしばらく開かないと消すことがある・アプリの中は そのアプリにだけ残る）と、置き方の手順（iPhone・Android・アプリの中で別々。LINE は `openExternalBrowser=1` で、ふだんのブラウザで開くリンク）を出す。Android で出せるときは「ホーム画面に追加」のボタン（beforeinstallprompt）。日記があれば「○件を書き出す」も（ホーム画面のほうは別の保存場所なので、書き出し→読みこみで移す）。「書く」を押したときも、開くたびに1回、先に置き方の窓を出す（「このまま書く」で書ける）。ホーム画面で開いて日記がまだないときは、移し方をひとこと。パソコンでは出さない。中身は `js/diary.js`・`js/diary-db.js`
- グラフは時刻を触ると全部そろって動く。夜（日の入り〜日の出）はうすい灰色。波・風・天気は1時間ごとの横スクロールの表も
- 風の向きは「16方位」と「角度」を切りかえられる（この端末に覚える）
- 朝まづめ・夕まづめ（めやす）：薄明のはじまり〜日の出の1時間後、日の入りの1時間前〜薄明のおわり
- iPhone のウィジェット：ページの「iPhone のウィジェットにする」から、Scriptable に入れるスクリプト（`SQriptableSea.js`）をコピーして、手順どおりに置く

## SQriptable とそろえるもの

場所から港・気象庁の地域を選ぶやり方、予報の種類、まづめの決め方は、SQriptable の sea カードと同じ（q-sqriptable の `docs/sea.md`）。片方を変えたらもう片方も。

## 公開のしかた

- いまは main を `.github/workflows/pages.yml` で GitHub Pages に出している（ためしの間）。出すときに Q キットの `qpublish.py` で CSS・JS に `?v=` を付ける（リポジトリの中には付けない）
- Q 共通の公開（katsuan/oqrn の `q-pages.yml`。テストは非公開の q-dev）に切りかえるときは、このリポジトリの secret に `Q_DEV_KEY` を登録してから `.github/workflows/pages.yml` を足す
- ページの下の「なかまのツール」の行は Q キットの `tool-share.js`（中身は q-oqrn の `data/hub-links.json` の umiqru）

## 出どころと使い方

- Open-Meteo（CC BY 4.0）：無料版は商用でない使い方だけ。呼ぶのは使う人のブラウザから直接
- 気象庁（防災情報の JSON）・tide736.net（潮汐表。海上保安庁の調和定数で計算。航海には使えない）・国土地理院（逆ジオコーダー）
- 予報は計算のめやす。海に出るかどうかは、気象庁の警報・注意報と現地のようすで決める
